was als Nächstes ansteht.

## 2. Was durchgeführt wurde

### 2.1 Neue Seite scharf geschaltet

Der Deploy-Workflow lieferte bis dahin in die Testumgebung und setzte dabei
`noindex`. Beides wurde umgestellt:

- Ziel in `.github/workflows/deploy-allinkl.yml`:
  `grh.vv-wildenstein.com` → `gruenhainichen.com`
- `PUBLIC_STAGING: 'true'` entfernt → kein `noindex` mehr
  (die Variable steuert das Meta-Tag in `BaseLayout.astro`)

### 2.2 WordPress Site 2 auf die Archiv-Domain umgezogen

Reihenfolge der Schritte auf dem Server:

1. Datenbank-Dump nach `_backup_golive_2026-08-16/db_vor_site2_umzug.sql` (225 MB)
2. `wp search-replace` über alle `snS6v_2_*`-Tabellen, in vier Durchgängen für
   die URL-Varianten `https://`, `http://`, `https://www.`, `http://www.` sowie
   protokollrelativ — zusammen rund **6.400 Ersetzungen**, danach 0 Reste
3. `snS6v_blogs`: Domain für `blog_id = 2` auf `alt.gruenhainichen.com`
4. `blog_public = 0` → Suchmaschinen ausgesperrt
5. Transients gelöscht, Objekt-Cache geleert

**Stolperstein für die Zukunft:** `wp search-replace` mit `--url` einer anderen
Site findet die Tabellen der Zweit-Site nicht und bricht mit
*„Couldn't find any tables matching"* ab. Nötig ist
`--all-tables-with-prefix`, sonst läuft der Befehl scheinbar erfolgreich
durch, ohne etwas zu ändern.

### 2.3 QR-Codes der Häusertafeln

Auf den Tafeln im Ort sind Codes physisch aufgedruckt, die auf
`gruenhainichen.com/tafel/{kürzel}/` zeigen. Die Regel dafür steht in
`apps/gruenhainichen/public/.htaccess`:

```apache
RewriteRule ^tafel/(.*)$ https://alt.gruenhainichen.com/tafel/$1 [R=301,L]
```

Getestet mit `g50`, `g1`, `b1` — alle drei landen über die Kette beim richtigen
Text:

```
www.gruenhainichen.com/tafel/g50/
  → alt.gruenhainichen.com/tafel/g50/
    → entdecke-gruenhainichen.de/tafel/das-kleine-armenhaus/#zusatzinfos
```

Die zweite Weiterleitung lag schon im alten WordPress und ist mit umgezogen.

> **Diese Regel erst entfernen, wenn die Tafeln tatsächlich woanders leben.**
> Siehe [MIGRATION-TAFELN.md](MIGRATION-TAFELN.md).

### 2.4 Aufgeräumt

| Was | Größe | Wie |
|---|---|---|
| Testumgebung `grh.vv-wildenstein.com` | 52 MB | gelöscht, Subdomain im KAS entfernt |
| Alte Nextcloud `cloud.vv-wildenstein.com` | 3,4 GB | archiviert, dann gelöscht |
| All-Inkl-Platzhalter | 85 KB | gelöscht |

**Zur Nextcloud:** Nextcloud 31.0.2 mit fünf Nutzerkonten, letzte
Dateiaktivität Januar 2025, letzter Log-Eintrag Juli 2025 — eine Altinstanz.
Die produktive Cloud läuft auf dem NAS. Vollständige Sicherung inklusive
Datenbank und Konfiguration liegt auf dem Server:

```
/www/htdocs/w01f6038/_archiv_nextcloud_2026-08-16.tar.gz   (1,3 GB, 128.425 Einträge)
```

Die MySQL-Datenbank `d0418a75` wurde **nicht** gelöscht; der Dump liegt im
Archiv.

### 2.5 Cloudflare-Worker gelöscht

Im Repo lag eine `wrangler.jsonc`, die einen Cloudflare-Worker
`vv-wildenstein-gruenhainichen` beschrieb. Der war noch mit dem GitHub-Repo
verbunden und baute bei jedem Push mit — unter
`vv-wildenstein-gruenhainichen.stefan-0ea.workers.dev` stand dadurch eine
öffentlich erreichbare, vollständige Zweitkopie der Gemeindeseite, ohne
`noindex` und mit erlaubender `robots.txt`.

Schaden entstand keiner: Das `canonical`-Tag zeigt auf
`www.gruenhainichen.com`, weil in `astro.config.mjs` die richtige Domain
eingetragen ist. Google ordnet die Kopie damit dem Original zu.

Worker im Dashboard gelöscht, `wrangler.jsonc` aus dem Repo entfernt. Die
Seite wird ausschließlich per rsync nach All-Inkl ausgeliefert; GitHub dient
als Sicherung.

**Merkposten:** Beim nächsten neuen Astro-Projekt daran denken, dass eine
`wrangler.jsonc` im Repo einen stillen Zweit-Deploy nach sich ziehen kann.

### 2.6 Broadcast-Plugin stillgelegt

`threewp-broadcast` und `threewp-broadcast-premium-pack` sind netzwerkweit
deaktiviert. Ihre Aufgabe war das Kopieren von Inhalten vom Verband nach
Grünhainichen; Astro holt sich alles direkt per REST, und Site 2 ist ein
eingefrorenes Archiv. Letzter Broadcast: 04.08.2026.

Dateien und die 936 Verknüpfungen in `snS6v__3wp_broadcast_broadcastdata`
liegen bewusst noch da, damit sich das rückgängig machen lässt.

Das mu-Plugin `wuw-broadcast-tile-image.php` hängt ausschließlich an
Broadcast-Hooks. Ohne Broadcast laufen die nie an — kein Fehler, nur toter Code.

## 4. Was noch offen ist

### Kurzfristig

- **Eine echte Tafel mit dem Handy scannen.** Alle Prüfungen liefen bisher über
  die Kommandozeile.
- **Google Search Console:** neue Seite anmelden, Sitemap
  `https://www.gruenhainichen.com/sitemap-index.xml` einreichen. Braucht ein
  Google-Konto der Gemeinde.
- **Subdomain `cloud.vv-wildenstein.com`** im KAS entfernen (Ordner ist weg).

### Mittelfristig

- **Tafeln umziehen** — 198 Einträge des CPT `tafel` samt Antjes Mediathek in
  ein anderes WordPress, siehe [MIGRATION-TAFELN.md](MIGRATION-TAFELN.md).
  Danach die `.htaccess`-Regel auf das neue Ziel umbiegen.
- **Antjes Rechte einschränken** — mu-Plugin `tafel-redaktion`, Entwurf liegt
  in der Migrationsanleitung.
- **Plugin-Inventur:** 31 netzwerkweit aktive Plugins, darunter sichtbare
  Dubletten (`pdf-embed` **und** `pdf-embedder`). `js_composer`, `us-core` und
  `welaunch-framework` sind der Unterbau des alten Themes — Astro braucht sie
  nicht, Site 2 schon.

### Bewusst zurückgestellt

**Die Multisite bleibt vorerst bestehen.** Site 2 hält weiterhin die Inhalte,
auf die die QR-Codes zeigen:

| Inhaltstyp auf Site 2 | Anzahl |
|---|---|
| `tafel` | **198** |
| `post` | 742 |
| `wpdmpro` | 125 |
| `amtsblatt_download` | 60 |
| Uploads | 3,6 GB |

Die Multisite aufzulösen hieße, Site 2 aufzugeben — und damit die Ziele der
Codes an den Häusern sowie Antjes Arbeitsplatz. Richtige Reihenfolge: erst die
Tafeln umziehen, Weiterleitung umbiegen, ein paar Wochen beobachten, dann
Site 2 abbauen.

Der Gewinn wäre auch danach überschaubar: Eine Multisite mit einer einzigen
Site ist unaufgeräumt, kostet aber weder Tempo noch Speicher. Die Umwandlung
dagegen berührt alle netzwerkweit aktivierten Plugins, die Tabellenpräfixe und
27 GB Uploads.

## 5. Prüfbefehle

Nach Änderungen an Domains oder Weiterleitungen:

```bash
for u in https://www.gruenhainichen.com/ https://alt.gruenhainichen.com/ https://vv-wildenstein.com/; do
  printf "%-40s " "$u"; curl -s -o /dev/null -w "%{http_code}\n" "$u"
done
```

Die QR-Kette bis zum Endziel:

```bash
curl -sL -o /dev/null -w "%{http_code}  %{url_effective}\n" https://www.gruenhainichen.com/tafel/g50/
```

Prüfen, dass die Archiv-Seite für Google gesperrt bleibt:

```bash
curl -s https://alt.gruenhainichen.com/ | grep -o 'name="robots" content="[^"]*"'
```
